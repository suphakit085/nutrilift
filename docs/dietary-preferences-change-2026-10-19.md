# ข้อจำกัดอาหาร: แยกชนิดข้อแพ้และเลือกขอบเขตการบันทึก

กรณีต้นเหตุ: โปรไฟล์ “วีแกน + แพ้ถั่ว” ไม่มีแหล่งโปรตีนที่ผ่านตัวกรอง เนื่องจากตัวเลือกแพ้ถั่วเดิมครอบคลุมถั่วเหลือง เต้าหู้ เทมเป้ และโปรตีนพืชทั้งหมด การหยุดเมนูภายใต้ข้อจำกัดเดิมยังคงอยู่ แต่ระบบให้ผู้ใช้ระบุชนิดและขอบเขตอย่างชัดเจนได้แล้ว

## พฤติกรรมใหม่

- หน้าโปรไฟล์ยุบตัวเลือกใน “ข้อจำกัดอาหาร — แก้ไข” แสดงรายการที่เลือก และแบ่งเป็นรูปแบบการกิน อาหารที่แพ้ และอาหารที่ไม่ต้องการ
- เพิ่มแพ้ถั่วลิสง แพ้ถั่วเปลือกแข็ง แพ้ถั่วเหลือง และแพ้งา โดยให้ตัวเลือก “แพ้ถั่ว — ยังไม่ระบุชนิด” ใช้ค่าเดิม `แพ้ถั่ว` ต่อไป ไม่มีการเปลี่ยนข้อมูลเก่าเป็นแพ้ชนิดใดอัตโนมัติ
- การแบ่งถั่วลิสง ถั่วเปลือกแข็ง และถั่วเหลืองเป็นคนละกลุ่มสอดคล้องกับ [รายการสารก่อภูมิแพ้ของ FDA](https://www.fda.gov/food/buy-store-serve-safe-food/food-allergies-what-you-need-know) การแบ่งกลุ่มไม่ได้รับรองว่าผู้ใช้คนหนึ่งกินกลุ่มอื่นได้ ผู้ใช้ต้องระบุข้อแพ้ที่ทราบทั้งหมด
- เมื่อขอเมนูโดยยังมีข้อแพ้ถั่วแบบไม่ระบุชนิด บอตถามเพิ่มพร้อมปุ่ม “ระบุข้อจำกัดอาหาร” และไม่เรียกโมเดลหรือจัดตารางอาหารแทน
- เปิดตั้งค่าจากหัวแชตได้เสมอเมื่อไม่มีคำตอบกำลังทำงาน แบบฟอร์มเริ่มจากข้อจำกัดที่มีผลจริงในห้อง รวมข้อมูลที่เพิ่งแจ้งทางข้อความและรายการที่ยังไม่รองรับ
- เลือก “ใช้เฉพาะห้องนี้” เพื่อเก็บการยืนยันในประวัติห้อง โปรไฟล์และประวัติโปรไฟล์ไม่เปลี่ยน ห้องใหม่เริ่มจากโปรไฟล์ตามเดิม
- เลือก “บันทึกในโปรไฟล์ด้วย” เพื่อเปลี่ยนเฉพาะรายการข้อจำกัด บันทึก revision พร้อมเป้าหมายจากข้อมูลกายภาพปัจจุบัน และใช้ได้ในห้องใหม่
- การนำข้อแพ้เดิมออกต้องยืนยันหลังตรวจรายการที่เลือกครบ รวมการเปลี่ยนตัวเลือกถั่วแบบรวมเป็นชนิดที่ระบุ ข้อจำกัดที่ยังไม่รองรับไม่ถูกลบโดยซ่อนจากแบบฟอร์ม
- ข้อมูลที่เปลี่ยนระหว่างเปิดแบบฟอร์มกับกดบันทึกถูกปฏิเสธด้วย 409 ให้โหลดข้อมูลล่าสุดก่อน การยืนยันจากห้องเก่ายังคงข้อแพ้ชนิดใหม่ที่เพิ่มในโปรไฟล์ภายหลัง
- ข้อจำกัดในโปรไฟล์ที่ไม่มีตัวกรองรองรับหยุดการจัดเมนู รวมค่าที่ API เคยเก็บไว้แบบอิสระ ไม่จัดเมนูแล้วเพียงเตือนว่าไม่ได้ใช้ข้อจำกัดนั้น

## การเก็บข้อมูลและ API

ใช้คอลัมน์ JSON ของ message เดิมสำหรับการยืนยันที่ผู้ใช้กดจริง โดยเพิ่ม metadata `set_dietary_preferences` พร้อมรายการ ขอบเขต และ snapshot รายการในโปรไฟล์ตอนยืนยัน เฉพาะ metadata บน user turn จาก endpoint ของผู้ใช้ที่เป็นเจ้าของห้องเท่านั้นที่นำมาใช้ ข้อความ/metadata ที่ assistant สร้างไม่สามารถล้างข้อแพ้ได้ เทิร์นที่ยกเลิกไม่นำมา replay

- `GET /dietary-options`: รายการตัวเลือกและ version สำหรับ client ที่ล็อกอินและผ่าน consent
- `PUT /profile/settings`: บันทึกโปรไฟล์ของ UI ใหม่; endpoint `PUT /profile` เดิมยังรองรับ client เดิม
- `GET /conversations/{id}/dietary-preferences`: รายการที่ใช้ในห้อง รายการในโปรไฟล์ และ context version
- `PUT /conversations/{id}/dietary-preferences`: ต้องส่งรายการ ขอบเขต และ context version; การนำข้อแพ้เดิมออกต้องส่งการยืนยันด้วย

ไม่มี migration หรือการแก้ข้อมูลอาหาร/ค่าต้นทาง การบันทึกถาวรใช้ transaction และ user lock ร่วมกับระบบ revision เดิม ตัวโมเดลไม่มีเครื่องมือเรียก API เปลี่ยนโปรไฟล์นี้เอง

## ผลทดสอบก่อนส่ง

- Backend regression: **1,465 ผ่าน**, 76 deselected ตามขอบเขต CI ไม่รวม PostgreSQL และ source audits ที่ต้องมีเอกสาร local
- ชุดที่เกี่ยวข้องก่อนเพิ่ม rollout guards: 230 ผ่าน; เพิ่ม 36 กรณีใหม่ที่อยู่ใน backend regression ครอบคลุมชนิดแพ้ การคงข้อมูลเดิม metadata จาก assistant ที่ใช้ไม่ได้ scope ownership stale context และประวัติ
- Frontend unit/contract: **94 ผ่าน**; lint, TypeScript และ production build ผ่าน
- Chrome กับ frontend build และ API/ฐานข้อมูล/SMTP ชั่วคราวจริง: **36 checks ผ่าน** รวม profile แบบยุบ การเลือกถั่วชนิดใหม่ การยืนยันการนำข้อแพ้เดิมออก ห้องใหม่ การ reload ประวัติ scope และลบบัญชีทดสอบ
- ใน 36 browser checks มี fault injection 2 สถานการณ์: capability endpoint ของ API รุ่นเก่าตอบ 404 และเครือข่ายล้มเหลวตอนบันทึก ข้อมูลไม่ถูกอ้างว่าบันทึกสำเร็จ และ retry ได้
- Candidate service กับ snapshot ฐานอาหาร production 386 รายการใน transaction read-only: **20 กรณี** ได้เมนู 14 แผน รวม **61 มื้อ** คำนวณย้อนจากค่าต้นทางตรงภายในการปัดเศษ โมเดลและ retrieval ถูกตั้งให้ล้มเหลวหากถูกเรียก แต่ไม่มีการเรียก
- เพิ่ม PostgreSQL ของ feature ใน workflow เดิม และเพิ่ม `npm run test:dietary-ui` ใน frontend CI ผล CI ของ commit ที่ส่งตรวจเป็นหลักฐานแยกจากผล local นี้

หลักฐาน local ของรอบนี้: `output/dietary-preferences-20261018/` และ `output/ci-cd/dietary-preferences/test-results/` ผล browser เป็นระบบทดสอบในเครื่อง ไม่อ้างว่า production รับแพตช์นี้แล้ว

## ขอบเขตที่ยังมี

- วีแกนร่วมกับแพ้ถั่วลิสงหรือถั่วเปลือกแข็งสามารถใช้แหล่งโปรตีนที่ผ่านข้อจำกัดได้ การรวมวีแกนกับแพ้ถั่วเหลืองยังอาจไม่มีแหล่งโปรตีนที่ planner รองรับ ระบบคงการหยุดและแจ้งข้อจำกัด ไม่ปลดข้อแพ้เพื่อให้สร้างตารางได้
- ตัวกรองยังอาศัยชื่อและประเภทอาหาร ไม่ใช่ฐานส่วนผสม/การปนเปื้อนทุกยี่ห้อ คำเตือนตรวจฉลากและการทบทวนโดยผู้เชี่ยวชาญยังคงอยู่
- ยังรองรับแผนหนึ่งวัน 3–6 มื้อตาม planner เดิม และยังไม่ตรวจราคาอาหาร
- คำถามที่ขอสูตรและเอกสารอ้างอิงไม่ครบ กับตำแหน่งคำเตือน BMI จากรายงาน UAT ก่อนเป็นงานแยกจากแพตช์นี้

หลัง backend และ frontend ขึ้นรุ่นนี้แล้ว ต้องตรวจเว็บจริงอีกครั้ง: บัญชีเดิมยังเห็นข้อแพ้ถั่วแบบรวม เลือกชนิดผ่านแชตได้ เลือก scope แล้วมีผลตรงกัน และลบบัญชีชั่วคราวหลังตรวจ
