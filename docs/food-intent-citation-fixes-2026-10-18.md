# แก้เจตนาไม่ใช้อาหารเสริมและอ้างอิงขั้นตอนใช้แอป — 18 ตุลาคม 2569

## ปัญหาและผลหลังแก้

จาก UAT production รุ่น `13ff408` คำขอ “อยากเพิ่มกล้าม ช่วยจัดเมนู 3 มื้อจากโปรไฟล์ ไม่เอาอาหารเสริม” ถูกแปลงเป็นข้อจำกัดที่ไม่รองรับ ทำให้จัดเมนูไม่ได้ แม้ถามต่อว่าใช้อาหารปกติก็ตาม อีกกรณี โมเดลนำแหล่งโภชนาการมาอ้างกับขั้นตอนเปิดโปรไฟล์และกดบันทึก

- แยกความชอบไม่ใช้อาหารเสริมเป็นเงื่อนไขที่ planner รองรับ กรองหมวดอาหารเสริมและชื่อโปรตีนผง/เวย์จริง ไม่ใช่เพียงละทิ้งข้อความที่ไม่รู้จัก
- รองรับคำขอไม่เอา/ไม่กิน/ไม่ใช้/ไม่ต้องการอาหารเสริม รวมตัวอย่างภาษาอังกฤษ และส่งต่อความชอบในห้องเดิม การประมวลผลประวัติใหม่ทำให้ followup หลังข้อความเดิมที่เคยล้มเหลวไม่ต้อง reset โปรไฟล์
- “มื้อเสริม” ยังคงเป็นตัวเลือกจำนวนมื้อคนละเรื่องกับ “อาหารเสริม” ไม่มีการเพิ่มสูตรอาหารหรือเปลี่ยนนโยบายปริมาณ
- คงข้อมูลแพ้อาหารจริงและโปรไฟล์เดิม คำว่า “แพ้อาหารเสริม” ที่ไม่ระบุส่วนประกอบยังต้องขอรายละเอียด ไม่ถือว่าการตัดอาหารเสริมรับรองความปลอดภัยจากการแพ้ทั้งหมด
- ทำความสะอาด citation ในข้อความนำทาง สถานะยังไม่ได้กรอกโปรไฟล์ และรายการขั้นตอน พร้อมรักษา citation โภชนาการในคำตอบเดียวกันและ Markdown links แหล่งที่แสดงยังผ่าน `cited_only` หลังทำความสะอาด
- เพิ่มคำสั่งแยกข้อความโภชนาการจากขั้นตอนใช้แอปใน prompt และเปลี่ยน `PROMPT_VERSION` จาก `v1.17.1` เป็น `v1.17.2` ไม่แก้ผล eval เก่าหรือฐานความรู้ย้อนหลัง

ตัวกรองข้อความเป็นกฎสำหรับรูปแบบขั้นตอนที่พบและทดสอบ ไม่ใช่ตัวพิสูจน์ความถูกต้องเชิงความหมายของทุก citation ที่โมเดลอาจสร้าง คำตอบเก่าที่บันทึกแล้วไม่ถูกเขียนใหม่

## การทดสอบ

ทดสอบ candidate บนฐาน `13ff408` ผ่าน frontend production build เดิมที่ชี้ loopback API ซึ่งรันโค้ดแพตช์ ใช้ PostgreSQL แยกและ Gemini จริง Seed เฉพาะความรู้สาธารณะ 26 documents / 59 chunks / 386 foods ด้วย transaction read-only ไม่คัดลอกบัญชีหรือประวัติผู้ใช้จริง

| ตรวจสอบ | ผล |
| --- | --- |
| Ruff app/tests/ingest และเครื่องมือ meal eval ที่ CI ตรวจ | ผ่าน |
| Backend regression รุ่นที่จะปล่อย | **1,185 ผ่าน**, 16 deselected ตาม scope CI (ไม่รวม postgres/evidence และ test_food_audit_fixes) |
| Compatibility ใน workspace ที่มีงาน auth ค้างอยู่ | **134 ผ่าน** |
| Browser UAT 3 persona: เพิ่มกล้าม / วีแกนแพ้นม / ยังไม่ตั้งโปรไฟล์ | **29/29 checks ผ่าน**, 10 คำถามในชุดสุดท้าย |
| Replay ผลเมนูที่บันทึกจริง รวมรอบทดสอบซ้ำ | **14/14 ผ่าน**: ยอดสารอาหาร ข้อจำกัด ปริมาณ และสถานะ tool ตรงกัน |

กรณีสำคัญ:

1. คำขอไม่เอาอาหารเสริมและ followup อาหารปกติ จัด 3 มื้อได้จริงโดยไม่มีเวย์/โปรตีนผง สำหรับ persona พลังงานสูงยังรายงาน **partial** และส่วนขาดตามจริง
2. อนุญาตมื้อเสริมแล้วขอ 6 มื้อรวม จัดได้โดยไม่มีอาหารเสริม ผลชุดนี้ **success** ไม่เพิ่มมื้อโดยพลการเมื่อผู้ใช้ระบุ 3 มื้อ
3. วีแกนและแพ้นมจัดเมนูโดยไม่ใช้อาหารเสริมได้ เมื่อเพิ่มแพ้ถั่วและหาโปรตีนที่ปลอดภัยไม่ได้ ระบบปฏิเสธแทนการฝืนเสนออาหาร
4. แพ้อาหารเสริมแบบไม่ระบุส่วนประกอบและ followup อาหารปกติยังถูกปฏิเสธเพื่อขอรายละเอียด
5. คำถามเดิม “เพิ่งสมัคร ยังไม่รู้ต้องกรอกอะไร อยากให้ช่วยจัดเมนูเพิ่มกล้ามให้หน่อย” แสดงขั้นตอนโปรไฟล์โดยไม่ติด S ส่วนคำอธิบายโภชนาการยังมีแหล่งที่ใช้จริง
6. คำถามวิจัยโปรตีนทั่วไปยังมี citation; reload ประวัติทั้งสี่กลุ่มได้ ไม่พบ JavaScript error และ viewport 390/1280 ไม่มีการล้นนอกหน้าในกลุ่มที่ตรวจ

การตรวจด้วยโมเดลจริงพบ citation หลุดท้าย numbered list ในแพตช์รอบแรก จึงเพิ่ม regression สำหรับรายการขั้นตอนและสถานะโปรไฟล์ แก้และทดสอบชุด browser ซ้ำกับ backend รุ่นสุดท้ายก่อนจัดทำผลนี้ ไม่ถือผลรอบแรกว่าผ่าน

หลักฐาน local: `output/playwright/uat-intent-20261018/` มี `backend.xml`, `workspace.xml`, `summary.json`, `chat-*.json`, `menu-verification.json` และภาพหน้าจอ พอร์ต 8039/3039 และฐานข้อมูลนี้เป็น candidate เท่านั้น ไม่ใช่หลักฐานว่า production ใช้แพตช์แล้ว

นำเฉพาะ diff ของ 7 ไฟล์กลับ workspace และตรวจ SHA256 ของงานค้างนอกแพตช์ **1,150 ไฟล์ไม่เปลี่ยน** ตาม `workspace-preservation.json`

## การปล่อยและขอบเขต

แพตช์นี้เป็น backend/prompt/tests ไม่มี migration หรือ dependency ใหม่ และไม่มี frontend source change ขึ้น PR แยกจากงาน auth และให้ hosted CI ผ่านก่อน merge จากนั้น Railway ต้อง deploy commit ใหม่ จึงจะยืนยันผลบนเว็บจริงได้ ไม่ถือ Vercel deploy หรือสถานะ Railway Active ของรุ่นเดิมเป็นการยืนยัน backend ใหม่

ยังต้องปิดงาน auth/Resend จริงก่อนเปิดรับผู้ใช้ทั่วไป รวมถึงทดสอบเข้า inbox และ lifecycle session งานถ้อยคำ safety และความอ่านง่ายของตารางเมนูมือถือยังอยู่ในรายการถัดไป ผลทดสอบนี้ไม่รับรองว่าโครงการทั้งหมดพร้อม production หรือว่าค่าปริมาณผ่านการรับรองจากนักกำหนดอาหารแล้ว

บัญชีสังเคราะห์และประวัติของรอบนี้อยู่เฉพาะ container ทดสอบ เมื่อเก็บหลักฐานครบให้ปิด browser/server และลบเฉพาะ container ที่มีชื่อและ label ของ campaign นี้
