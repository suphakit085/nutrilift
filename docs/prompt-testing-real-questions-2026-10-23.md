# รายงาน prompt testing ด้วยคำถามจริงจากผู้ใช้ภาษาไทย (23 ต.ค. 2569)

> **สถานะของผลตรวจ:** ผลตรวจรายข้อในรายงานนี้เป็น**ผลตรวจเบื้องต้นโดย AI (Claude)** ตามพฤติกรรมที่คาดหวังซึ่งล็อกไว้ก่อนรัน ยังไม่ได้ผ่านการตรวจของผู้จัดทำและผู้เชี่ยวชาญ ช่องให้ผู้จัดทำและผู้เชี่ยวชาญตรวจอยู่ใน [`review-th.csv`](../eval/reports/real-questions-4fca71e/review-th.csv) จึงยังไม่ควรอ้างตัวเลขนี้เป็นผลประเมินสุดท้าย

## 1. วัตถุประสงค์

อาจารย์ที่ปรึกษาให้ข้อเสนอแนะว่า
- คำถามทดสอบส่วนใหญ่ไม่ควรเป็นคำถามที่ให้ AI แต่ง ควรใช้คำถามจริงจากผู้ใช้
- ต้องทำ prompt testing และบันทึกผลไว้ใส่ในเล่ม

รายงานนี้จึงทดสอบแชตของ NutriLift ด้วยคำถามที่คนโพสต์จริงบนเว็บสาธารณะ ผ่านเส้นทางโค้ดเดียวกับ production และบันทึกวิธีทดสอบ ผลดิบ และผลตรวจรายข้อไว้ทั้งหมด

**ชุดแกนกลาง 20 ข้อ** (`core-subset.json`) รันซ้ำ 3 รอบเพื่อดูความคงที่ เลือกด้วยกฎที่กำหนดไว้ก่อนเลือก โดยดูจากหมวดหมู่และถ้อยคำเท่านั้น ไม่ดูผลทดสอบ

### 8.1 ผล probe ตัวตีความเมื่อทดลองแก้ pair_partner

ทดสอบเฉพาะขั้นตีความกับ Gemini จริง ใช้โปรไฟล์ตัวอย่างเดิม โดยรันคำถามจริงทั้ง 61 ข้อ ข้อละ 1 รอบ และประโยคจับคู่/เปรียบเทียบ 6 ประโยค ประโยคละ 3 รอบ เทียบระหว่าง main กับ branch ที่แก้ ไฟล์อยู่ใน `eval/reports/real-questions-4fca71e/pair-probe/`

**ผลบน branch (79 ครั้ง ไม่มี error)**
- TH22 (ผอมมีพุง เพิ่มกล้ามหรือลดไขมัน) ตอบได้
- ประโยคเปรียบเทียบที่สร้างไว้ทดสอบ P04 (ข้าวกล้องกับข้าวขาว) และ P06 (เวย์คู่กับนม) ตอบได้ทั้ง 3 รอบ
- ประโยคที่ละอีกฝั่งไว้จริง P01 (เวย์ทานคู่กับ ..) และ P02 (ครีเอทีนคู่กับ ...) ยังถามกลับทั้ง 3 รอบ ซึ่งถูกต้อง
- **แต่ TH11 ยังถามกลับ** โมเดลเปลี่ยนช่องที่ขาดจาก `pair_partner` เป็น `other` ซึ่งโปรแกรมไม่ได้ตรวจ
- **มีข้อที่ main เคยตอบได้กลายเป็นถามกลับแบบ `other`** ได้แก่ TH12 และ TH13 และใน branch YT04 ก็ถามกลับแบบ `other` (ผล main ของ YT04 ไม่ได้ เพราะโควตาหมด แต่ในรอบหลัก YT04 ได้คำตอบ)
- โมเดลยกคำในช่องใหม่เพี้ยนบางครั้ง เช่น ตัวอักษรอาหรับ หรือคำไทยเพี้ยน โปรแกรมจึงไม่นับคำเหล่านั้น ส่วนนี้ไม่ทำให้ผลผิด แต่แสดงว่าการเพิ่มช่องทำให้โมเดลเขียนข้อความเพี้ยนได้

**ผลบน main:** ได้เพียง 24 จาก 79 ครั้ง เพราะโควตารายวันของ test key หมดระหว่างรัน

**ข้อสรุป:** การเพิ่มช่องใน schema เปลี่ยนพฤติกรรมของโมเดลเกินกว่าข้อที่ตั้งใจแก้ และทำให้มีการถามกลับเพิ่มขึ้นในข้อที่เคยตอบได้ จึง**ไม่นำมาใช้**ตามหลัก merge เฉพาะเมื่อไม่ถอยลง เก็บ patch ไว้ใน `pair-probe/pair-grounding-not-adopted.patch` ทางที่ควรลองต่อคือไม่ตัดถามกลับก่อนเรียกโมเดลสำหรับกรณีจับคู่ แล้วให้โมเดลตอบหรือถามกลับเอง แต่ต้องทดสอบก่อน

## 9. ข้อจำกัด

- **ผู้ตรวจ:** ทั้งพฤติกรรมที่คาดหวังและผลตรวจทำโดย AI คนเดียว ต้องให้ผู้จัดทำและผู้เชี่ยวชาญตรวจ
- **ลักษณะคำถาม:**
  - ส่วนใหญ่เป็นชื่อกระทู้ ซึ่งไม่มีบริบทจากตัวโพสต์
  - เลือกตามหัวข้อของโครงการ ไม่ได้สุ่มจากผู้ใช้ทั้งหมด
  - ข้อความสาธารณะอาจอยู่ในข้อมูลฝึกของโมเดลแล้ว
- **โปรไฟล์ตัวอย่างเดียว:** ไม่ได้ทดสอบโปรไฟล์หลายแบบ เช่น หญิง วัยรุ่น หรือ BMI สูง ในชุดคำถามจริง
- **การค้นคืนที่ล็อกไว้:** วัดคุณภาพการตอบ ไม่ได้วัดความผันผวนของการค้นคืน
- **ความไม่คงที่:** โมเดลไม่ได้ให้ผลเดิมทุกครั้ง ผลรอบเดียวของแต่ละข้อจึงมีความคลาดเคลื่อน
- **ผู้ให้บริการ:** Gemini free tier มีโควตารายวันและบางช่วงตอบช้าหรือขัดข้อง ส่งผลต่อเวลาและอาจทำให้วันนำเสนอไม่ได้คำตอบ
- **ยังไม่ได้ทดสอบบนเว็บจริง** ในรายงานนี้ ผลทดสอบผู้ใช้จริงบน production จะบันทึกแยก

## 10. ปัญหาที่ยังเปิดอยู่

1. ตีความคำถามเปรียบเทียบเป็นการจับคู่ที่ขาดอีกฝั่ง (TH11, TH22, TH42) ทางแก้ที่ลองแล้วไม่ผ่าน ดูหัวข้อ 8.1
2. ตัวตรวจคำตอบปัดตกทั้งคำตอบเมื่อมีประโยคที่หลักฐานไม่รองรับ แม้ประโยคนั้นถูกต้อง ทางแก้ที่เป็นไปได้คือตัดเฉพาะประโยคแล้วส่งส่วนที่เหลือ (fail-soft) แต่ยังไม่ได้ทำ
3. คลังความรู้ 26 ใบไม่ครอบคลุมบางหัวข้อที่ถามบ่อย เช่น แหล่งอาหารของครีเอทีน คีโตกับประเภทการออกกำลังกาย เวย์ก่อนนอน และแหล่งโปรตีนมังสวิรัติ
4. ขั้นตีความยังเขียนข้อความอ้างอิงเป็น Unicode escape ที่เพี้ยนได้ (2 จาก 101 ผล)
5. TH48 ถูกส่งไปค้นฐานข้อมูลอาหารผิด
6. เวลาตอบยาวและเรียกโมเดลหลายครั้งต่อคำถาม (มัธยฐาน 5 ครั้ง)
7. นโยบายคำถามเรื่องไตยังไม่สม่ำเสมอระหว่าง YT08 กับ YT09
