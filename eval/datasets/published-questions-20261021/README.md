คำถามคัดจากข้อความที่เผยแพร่จริง ไม่ให้ AI สร้างคำถามใหม่ ไม่ใช่คำถามของผู้ใช้ NutriLift และไม่รับรองตัวตนหรือวิธีเขียนของผู้โพสต์ การเรียก “คำถามจริง” หมายถึงตรวจพบชื่อคำถามบนแหล่งที่เชื่อมโยงได้ ไม่ได้พิสูจน์ว่าทุกข้อความเขียนโดยมนุษย์

## วิธีเก็บและข้อจำกัด

- Pantip: เลือกกระทู้ที่เกี่ยวกับโปรตีน อาหารเสริม พลังงาน อาหาร และการเปลี่ยนน้ำหนัก ตรวจ `<title>` ถอด HTML entities และตัดเฉพาะ suffix ` - Pantip` ไม่เกลาภาษา ชื่อไม่ใช่เนื้อหากระทู้ทั้งหมดและไม่มีข้อมูลผู้โพสต์ส่วนตัวในไฟล์
- ภาษาอังกฤษ: `GET https://api.stackexchange.com/2.3/questions` โดย `site=fitness`, `pagesize=100`, `sort=votes`, `order=desc`, `todate=1577836799` แยกแท็ก nutrition, diet, protein, supplements, weight-gain, weight-loss ตามลำดับ ถอด HTML entities ในชื่อ ตัดซ้ำด้วย question ID แล้วเก็บ **150 รายการแรก** ไม่สุ่มและไม่ได้แบ่งจำนวนเท่า ๆ กันตามแท็ก การเลือกแบบนี้เอนเอียงไปตามลำดับแท็กและความนิยม
- วันที่ตีพิมพ์ก่อนปี 2020 ของภาษาอังกฤษลดความเกี่ยวข้องกับยุคข้อความ AI สมัยใหม่ แต่ไม่ได้ยืนยันความเป็นมนุษย์หรือความเหมาะสมของคำถามสำหรับระบบปัจจุบัน
- ข้อมูลเก่าอาจอยู่ในชุดฝึกของโมเดลแล้ว จึงไม่อ้างว่าคำถามเหล่านี้ใหม่สำหรับโมเดลหรือปราศจากการปนเปื้อนจากชุดฝึก
- ทุกแถวมี URL เวลาเก็บ และ SHA-256 ของชื่อหลังขั้นตอนข้างต้น ภาษาอังกฤษเก็บชื่อผู้เขียนสาธารณะ ลิงก์เครดิต และ `content_license` ตาม API ต้องรักษาเครดิต/สิทธิ์เมื่อเผยแพร่ต่อ
- เก็บชื่อแต่ละคำถามเพื่อชี้กลับต้นทาง ไม่เก็บหรือคัดลอกบทความ/คอมเมนต์ทั้งหมด ไม่ใช้คำตอบผู้ใช้ในเว็บเป็นเฉลยโภชนาการ
- API ไม่ส่งข้อมูล license สำหรับคำถามอังกฤษ 28 รายการ จึงคงค่าว่างและทำเครื่องหมายรอตรวจ ไม่เดา license จากอายุข้อความ ส่วน Pantip ยังไม่ได้ตรวจสิทธิ์การเผยแพร่ซ้ำ ต้องตรวจสิทธิ์/เครดิตก่อนนำไปแจกจ่ายเป็นชุดข้อมูลสาธารณะ ทั้งสองกรณียังเก็บ URL ต้นทางครบ
- ภาษาอังกฤษ **ยังไม่แปลไทย** ถ้าแปลภายหลัง ต้องแยก `question_original` กับคำแปลและวิธีแปล ให้คนตรวจความหมาย ไม่เรียกคำแปลว่าเป็นข้อความไทยต้นฉบับจากผู้ใช้
- เก็บประวัติ HTTP/จำนวนที่ได้ใน `thai-acquisition.json` และ `question-acquisition.json` ไม่รายงานข้อมูลชุดนี้เป็นผลสำเร็จของตัวแชตบอต

## ก่อนนำไปทดสอบ

1. เปิด URL อ่านบริบทจริง ตรวจอายุ โรค เป้าหมาย ข้อมูลที่ขาด และความเสี่ยง ชื่อ “กินน้อย แต่น้ำหนักไม่ลด” อย่างเดียวอาจซ่อนพฤติกรรมจำกัดพลังงานมากในเนื้อเรื่อง ถ้าใช้ title-only ต้องประเมินตามข้อมูลที่โมเดลได้เห็นและห้ามให้คะแนนเสมือนรู้บริบทที่ซ่อนอยู่
2. เลือกรูปแบบให้คงที่: title-only พร้อมสิทธิ์ถามกลับ หรือชื่อพร้อมสรุปบริบทที่ตรวจเทียบต้นฉบับ ต้องระบุการตัดต่อ/ปกปิดข้อมูลและ hash เวอร์ชัน ห้ามเติมข้อมูลอายุ/น้ำหนักที่ต้นทางไม่มี
3. กำหนดหมวด/เฉลยก่อนรัน: ประเด็นที่ต้องตอบ หลักฐานวิชาการรองรับ สิ่งที่ไม่ควรตอบ ความจำเป็นต้องถามเพิ่มหรือส่งต่อ และคะแนนตาม rubric เดิม 0–2 แยก correctness/grounding/completeness/relevance กรณีไม่มีหลักฐานให้แยก N/A ไม่รวมตัวหารโดยไม่บอก
4. ให้ผู้จัดทำและผู้เชี่ยวชาญตรวจเฉลย/ขอบเขตที่เกี่ยวข้อง ระบุผู้ตรวจและวันที่จริง ไม่กรอกว่าตรวจแล้วอัตโนมัติ การใช้ AI ช่วยร่างเฉลยต้องเก็บประวัติว่า AI ช่วยและให้คนตรวจอีกครั้ง
5. คัดจำนวนและสัดส่วนตามวัตถุประสงค์ก่อนดูคำตอบระบบ ไทย/อังกฤษไม่ควรปนคะแนนโดยไม่แยกภาษา เพิ่มแหล่งและหมวดที่ยังขาดเพื่อบรรเทาความเอนเอียง ไม่อ้างว่าชุดที่เลือกสะท้อนผู้ใช้ทั้งหมด
6. ตรวจซ้ำเชิงความหมายกับ 135 ข้อเดิมและคำถามที่ใช้ปรับ prompt แล้ว ชุดที่เปิดอ่านเพื่อพัฒนาระบบแล้วถือเป็น development ควรเก็บชุดทดสอบสุดท้ายใหม่หลัง freeze prompt/policy ไม่เรียกผู้สมัครในไฟล์นี้ว่า held-out เพียงเพราะเปลี่ยนชื่อไฟล์
7. รันทั้ง RAG/ไม่มี RAG ด้วยคำถามและ configuration เดียวกัน เก็บข้อความส่งจริง คำตอบ error/timeout แหล่งค้นคืน prompt/model/version เวลา และ seed ถ้ามี ห้ามเลือกเฉพาะรอบที่ตอบดี คะแนนและตัวหารต้องรายงานทั้ง error และคำถามที่ถูกตัดด้วยเหตุผลที่กำหนดล่วงหน้า

ยังคง `human_review_status=pending`, `evaluation_status=not_run`, `selection_status=candidate_not_held_out` และเฉลยว่างไว้ตามจริง นี่เป็นการเตรียมชุดใหม่แยกจาก 135 ข้อเดิม ไม่ลบหรือแก้ย้อนหลังว่าข้อเดิมมาจากสื่อจริง
